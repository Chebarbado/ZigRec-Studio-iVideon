Как написать программу для камеры IvideonHow to build an Ivideon camera app

Два пути: (1) через облако по логину и паролю — рабочий, проверенный; (2) прямое подключение к камере — исследование не закончено. Работайте только со своим аккаунтом и своей камерой. Two paths: (1) via the cloud with a login and password — working and verified; (2) a direct connection to the camera — research still open. Use it only with your own account and your own camera.

1. Через облако (login:pass) — рабочий путь1. Via the cloud (login:pass) — the working path

Живое видео идёт через облако Ivideon. Шесть шагов:

Live video goes through the Ivideon cloud. Six steps:

Шаг 1 — входStep 1 — sign in

OAuth2 password-grant, публичный клиент android-client с пустым секретом. api.ivideon.com редиректит на живой хост авторизации openapi-alpha-eu01.ivideon.com.

OAuth2 password grant, public client android-client with an empty secret. api.ivideon.com redirects to the live auth host openapi-alpha-eu01.ivideon.com.

POST https://openapi-alpha-eu01.ivideon.com/auth/oauth/token?client_id=android-client
Authorization: Basic YW5kcm9pZC1jbGllbnQ6      # base64("android-client:")
Content-Type: application/x-www-form-urlencoded

grant_type=password&username=EMAIL&password=PASS
&client_type=android&client_version=3.7.1
&device_instance_id=UUID&device_type=...&device_name=...&trusted_device=true

Шаг 2 — двухфакторная авторизация (если включена)Step 2 — two-factor auth (if enabled)

Ответ приходит 200 с proceed_with_2fa, challenge_token, api5_host и списком методов (SMS/email). Выбираем метод — сервер шлёт код — отправляем код:

The response is 200 with proceed_with_2fa, challenge_token, api5_host and a list of methods (SMS/email). Select a method — the server sends a code — submit it:

POST https://{api5_host}/two_factor_methods/{id}?op=SELECT   {"challenge_token": "..."}
POST https://{api5_host}/two_factor_methods/{id}/code?op=SUBMIT   {"challenge_token": "...", "code": "123456"}   → token

Шаг 3 — токенStep 3 — the token

В ответе: access_token, refresh_token, hmac_secret (ключ подписи стримов) и api_host (база для всех дальнейших запросов).

The response has access_token, refresh_token, hmac_secret (the stream-signing key) and api_host (the base for every later request).

Шаг 4 — список камерStep 4 — the camera list

POST https://{api_host}/servers?op=FIND&access_token=TOKEN
{"projection": { ... }, "include_all": true}
→ {"success": true, "result": {"items": [ { "id": "100-...:0", "name": "...", "online": true, ... } ]}}

id камеры — вида <сервер>:<индекс>.

The camera id looks like <server>:<index>.

Шаг 5 — подписанный URL потокаStep 5 — the signed stream URL

К URL добавляются access_token и cseq, затем считается cs:

Add access_token and cseq to the URL, then compute cs:

path  = /cameras/{id}/live_stream
query = q=1&video_codecs=h265,h264&audio_codecs=pcmu,pcma,aac,mp3&access_token=TOKEN&cseq=SESSION:COUNTER
        # SESSION = 8 симв [0-9a-zA-Z] / 8 chars ; COUNTER = монотонные мс / monotonic ms ; query — URL-кодирован
cs    = hex( HMAC_SHA1( hmac_secret, hex( SHA1( "GET:" + path + ":" + query + ":" ) ) ) )
URL   = https://{api_host}{path}?{query}&cs={cs}

Шаг 6 — видеоStep 6 — the video

Тело ответа этого URL — FLV поверх HTTPS с H.264/H.265 и звуком AAC/G.711. Открывается плеером/ffmpeg напрямую. Отдельный кадр (JPEG): GET /cameras/{id}/live_preview?q=.

The body of that URL is FLV over HTTPS with H.264/H.265 and AAC/G.711 audio. It opens in a player/ffmpeg directly. A single frame (JPEG): GET /cameras/{id}/live_preview?q=.

# ffmpeg / ffplay открывает подписанный URL как есть / opens the signed URL as-is:
ffplay "https://{api_host}/cameras/{id}/live_stream?...&cs=..."
ffmpeg -i "https://...&cs=..." -c copy out.mp4

Готовые реализации: watch_camera.py (вход + 2FA + подпись, Python) и модули Zig src/net/ivideon.zig, src/capture/camera.zig. Точные поля и подводные камни кодирования — в разделах Авторизация, Подпись URL, Видео.

Ready implementations: watch_camera.py (login + 2FA + signing, Python) and the Zig modules src/net/ivideon.zig, src/capture/camera.zig. Exact fields and encoding pitfalls are in Authorization, URL signing, Video.

2. Прямое подключение к камере — исследование (не закончено)2. Direct connection to the camera — research (unfinished)

Что выяснено:

  • Ivideon Cute 2 — OEM камеры Huacheng/EZVIZ (семейство Hikvision): MAC OUI 30:24:50 её Wi-Fi-точки → Hangzhou Huacheng Network Technology.
  • В режиме настройки камера поднимает собственную Wi-Fi-точку Camera-<serial> (WPA2), рядом (сигнал 95%).
  • По USB камера не отдаёт ничего — на USB не перечисляется никак, кабель только для питания.

Гипотезы (не подтверждены):

  • Локальный RTSP по схеме EZVIZ: rtsp://admin:<verification-code>@<ip>:554/H.264 (или /Streaming/Channels/101).
  • ONVIF (порт 80/8000, WS-Discovery → GetStreamUri).
  • Локальный HTTP setup-API EZVIZ.

Что помешало проверить: пароль точки (verification code) не на основной наклейке (там S/N и MAC); активный VPN заворачивал локальную сеть в туннель.

Статус: открыто. Если фирменная прошивка Ivideon не заблокировала локальный доступ — картинку можно получить без облака. Детали и план проверки — в Привязке камеры и Открытых вопросах.

What we found:

  • The Ivideon Cute 2 is an OEM of a Huacheng/EZVIZ camera (Hikvision family): the MAC OUI 30:24:50 of its Wi-Fi AP resolves to Hangzhou Huacheng Network Technology.
  • In setup mode the camera raises its own Wi-Fi AP Camera-<serial> (WPA2), right next to the PC (95% signal).
  • Over USB the camera exposes nothing — it does not enumerate on USB at all; the cable is power only.

Hypotheses (not confirmed):

  • Local RTSP, the EZVIZ way: rtsp://admin:<verification-code>@<ip>:554/H.264 (or /Streaming/Channels/101).
  • ONVIF (port 80/8000, WS-Discovery → GetStreamUri).
  • A local EZVIZ HTTP setup API.

What blocked verification: the AP password (the verification code) is not on the main label (which has only the S/N and MAC); an active VPN routed the local network into its tunnel.

Status: open. If Ivideon's OEM firmware did not disable local access, the picture can be obtained without the cloud. Details and a check plan are in Camera attachment and Open questions.
