## 1.3. Как воспроизвести декомпиляцию

```bat
:: 1. XAPK — это zip. Распаковать в apk\xapk\
:: 2. Декомпилировать base APK
set JAVA_HOME=%CD%\tools\jre
tools\jadx\bin\jadx.bat --deobf --show-bad-code -d decompiled-ivideon-3.7.1 apk\xapk\com.ivideon.client.apk
```

* `--deobf` — заменяет короткие/конфликтующие имена на уникальные вида `C2199ku`, `InterfaceC2236lu`, `m14706Q`, `f26461g`. **Имена детерминированы**: при той же версии jadx и тех же опциях получатся те же имена, поэтому ссылки вида `p000/C2199ku.java` в документации стабильны. При другой версии jadx имена «поедут» — ориентируйтесь тогда на комментарий `/* renamed from: ku */` (это настоящее имя класса в DEX) и на строковые литералы.
* `--show-bad-code` — оставляет в выводе методы, которые декомпилировались с ошибками. Таких 223 из 11 746 классов (лог: `tools/jadx-ivideon.log`). В тексте они помечены `JADX WARN`/`JADX ERROR`; некоторые выведены только заглушкой `Method dump skipped` (пример — `C2199ku.m14118a`). Для них нужен просмотр smali/байткода (`jadx --comments-level debug` или jadx-gui).

Результат: `decompiled-ivideon-3.7.1/sources/` (Java) и `decompiled-ivideon-3.7.1/resources/` (манифест, `res/`, assets).

## 1.4. Структура декомпилированного кода

| каталог в `sources/` | что там |
|---|---|
| `p000/` | **почти весь код приложения** после R8: классы без пакета, имена 2–3 символа. Здесь сервисы API, DTO, интерцепторы, репозитории, ViewModel-и |
| `com/ivideon/client/` | то, что R8 не переименовал: Activity/Fragment/Service из манифеста, UI (`p009ui/player`, `p009ui/wizard`) |
| `com/ivideon/sdk/network/data/error/` | иерархия ошибок API — имена сохранены (65 классов + `export/`, `timelapse/`) |
| `com/ivideon/sdk/player/p014iv/core/IvPlayer.java` | JNI-обёртка нативного плеера — имена `native`-методов сохранены (иначе не слинкуется) |
| `okhttp3/`, `retrofit2/`, `kotlin/`, `kotlinx/`, `androidx/`, `coil3/`, `io/`, `ru/` … | сторонние библиотеки; частично переименованы, часть их классов «уехала» в `p000/` |

Сегменты пакетов вида `p009ui`, `p014iv`, `p012v5` — это jadx переименовал `ui`, `iv`, `v5` (слишком короткие имена). Реальные пакеты: `com.ivideon.client.ui`, `com.ivideon.sdk.player.iv.core`, `com.ivideon.sdk.network.data.v5`.

## 1.5. Как читать обфусцированный код

### Что переживает обфускацию

R8 переименовывает классы, методы и поля, но **не трогает**:

1. **Строковые литералы** — пути API (`"/cameras/{cameraId}/live_stream"`), JSON-ключи (`"access_token"`), лог-сообщения (`"Update token: refresh (1) starting..."`), имена алгоритмов (`"HmacSHA1"`). Это главный инструмент навигации: поиск по строке почти всегда выводит на нужный класс.
2. **Значения аннотаций** — пути Retrofit и имена JSON-полей Gson лежат в аннотациях как строки.
3. **Имена `native`-методов и классов из манифеста.**
4. **Ссылки на методы Kotlin** — при компиляции `::signWithSecret` в байткод попадает исходное имя и сигнатура. Так восстановлено имя `signWithSecret(Ljava/lang/String;)Ljava/lang/String;` (`p000/C2470s2.java:22`).

### «Классы-швейцарские ножи»

R8 склеивает много мелких лямбд и классов в один (class merging). Такой класс имеет поле-дискриминатор `int` (обычно `f…a`) и `switch` по нему в каждом методе. Примеры: `g58`, `kr6`, `qv5`, `C2504t`. В них **99 % кода не относится к Ivideon** (Compose, CameraX, Firebase, protobuf…). Читать надо только нужную ветку:

| класс | нужная часть | как найти |
|---|---|---|
| `p000/g58.java` | метод `mo7583n` — интерцептор авторизации и подписи | создаётся как `new g58(7, i85Var)` в `C2199ku` |
| `p000/kr6.java` | конструктор `kr6(C2504t)` (строки 626–647) — генерация идентификатора сессии | `this.f26374a = 7` |
| `p000/qv5.java` | конструктор `qv5(i85, ry1)` (697–701) и метод `m17621g` (358–366) — форма OAuth | `this.f36623a = 6` |
| `p000/C2504t.java` | `case 1` (119–138) — `signWithSecret`, HMAC-SHA1 | по строке `"HmacSHA1"` |

### Словарь аннотаций сетевого слоя

Сетевой слой — Retrofit 2 + OkHttp + **Gson**. Аннотации Retrofit и собственные аннотации Ivideon переименованы; соответствие восстановлено по их форме (наличие `value()`, `encoded()`, `alternate()`) и по использованию.

| обфусц. | оригинал | смысл |
|---|---|---|
| `@wy6("…")` | `retrofit2.http.POST` | метод POST, путь |
| `@mg4("…")` | `retrofit2.http.GET` | метод GET, путь (пустой — если URL динамический) |
| `@g47("x")` | `retrofit2.http.Path` | подстановка в `{x}` |
| `@fp7("x")` | `retrofit2.http.Query` | query-параметр; `null` — параметр опускается |
| `@ey0` | `retrofit2.http.Body` | тело запроса, сериализуется Gson в JSON |
| `@iba` | `retrofit2.http.Url` | полный URL передаётся аргументом |
| `@xa4` | `retrofit2.http.FormUrlEncoded` | тело `application/x-www-form-urlencoded` |
| `@zz3` | `retrofit2.http.FieldMap` | карта полей формы (есть `encoded()`) |
| `@bo4` | `retrofit2.http.HeaderMap` | заголовки аргументом (есть `allowUnsafeNonAsciiValues()`) |
| `@ok8("x")` | `com.google.gson.annotations.SerializedName` | имя JSON-поля (есть `alternate()`) |
| `@mn6` | собственная Ivideon | публичный запрос — токен не добавляется |
| `@zc0` | собственная Ivideon | токен в заголовке `Authorization: Bearer` |
| `@l85` | собственная Ivideon | стримовый URL — подписывается (`cseq`, `cs`) |
| `@kr7` | собственная Ivideon | метод возвращает `String` — «сырой» JSON, который разбирается вручную выше по стеку |

Прочие типы: `ek6<T>` — обёртка вызова (аналог `retrofit2.Call<T>` с колбэками статуса), `sn6` — пустой результат-синглтон («данных нет, важен только успех»), `v28` — `okhttp3.ResponseBody` (бинарный ответ), `ct5` — DTO `LivePreviewChannel{url}` (имя видно в его `toString()`), `ps4` — `okhttp3.HttpUrl`, `e82` — `HttpUrl.Builder`, `g08` — `okhttp3.Request`, `a40` — `Request.Builder`, `fo4` — `okhttp3.Headers`.

### Рецепты поиска

| задача | приём |
|---|---|
| найти все эндпоинты | grep по `@wy6\("` и `@mg4\("` в `p000/` — их объявляют только интерфейсы сервисов |
| найти JSON-поля запроса/ответа | открыть класс-аргумент `@ey0` или параметр типа `ek6<…>`, читать `@ok8("…")` |
| найти, кто вызывает эндпоинт | grep по имени метода с префиксом `m` и номером, например `m14706Q\(` |
| найти значения enum | открыть enum; у «строковых» enum значение — аргумент конструктора (`UP("up")`), а `toString()` его и возвращает |
| найти, куда уходит значение поля DTO | grep по геттеру (`m7191e\(` для `api_host`) |
| понять ветку класса-ножа | найти `new <класс>(N, …)` и читать `case N` |

## 1.6. Уровни достоверности

Во всей документации используются пометки:

| пометка | значение |
|---|---|
| **[код]** | прямо видно в декомпилированном коде; указаны файл и строки |
| **[вывод]** | логическое следствие из кода, но не дословно написано в нём |
| **[гипотеза]** | предположение; нужно проверить |
| **[проверено]** | подтверждено реальным запросом к серверу или запуском |

<!-- figure: confidence-levels | Пометки достоверности, которыми размечен весь текст -->

На момент написания **[проверено]** только: редиректы хостов (`api.ivideon.com` → `eu01-api.ivideon.com`) и совпадение реализации подписи в `zig-client/src/sign.zig` с независимой реализацией на Python. **Ни один авторизованный запрос к живому API ещё не выполнялся**. Поведение сервера (коды ошибок, точные формы ответов, лимиты) известно только в той мере, в какой его отражает код клиента.

## 1.7. Правовые и этические рамки

Исследование ведётся для совместимости с **собственной** камерой и **собственным** аккаунтом пользователя. Документация не содержит учётных данных, токенов и способов обхода чужой авторизации. `client_id` `android-client` с пустым секретом — публичная константа из приложения, а не секрет. Условия использования сервиса Ivideon и ограничения по частоте запросов не изучены — при живых проверках не создавайте нагрузку: единичные запросы, без циклов опроса быстрее, чем это делает само приложение.
