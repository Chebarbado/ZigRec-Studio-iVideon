# 13. Открытые вопросы и план живой проверки

**Теги:** #открытые_вопросы #живая_проверка #риски #безопасность

Вся документация построена на **статическом анализе**. Этот раздел отделяет известное от неизвестного и описывает, в каком порядке проверять протокол на реальном аккаунте, не навредив ни аккаунту, ни камере.

## 13.1. Что проверено фактически

| утверждение | как |
|---|---|
| `api.ivideon.com` редиректит на `eu01-api.ivideon.com`; `openapi-alpha.ivideon.com` → `openapi-alpha-eu01.ivideon.com` | запрос без авторизации |
| Cute 2 по USB не определяется в Windows никак (только питание) | осмотр PnP-устройств |
| реализации подписи на Zig и Python совпадают на трёх векторах | `zig build test`, прогон кода из [05-url-signing.md](05-url-signing.md) |

Всё остальное — чтение кода клиента.

## 13.3. Вопросы, требующие отдельной работы

| вопрос | путь решения |
|---|---|
| Смысл аргументов `nativeSetMedia`, коды ошибок плеера, метаданные FLV (`syncTime`, `fragmentPosition`) | дизассемблирование `libivplayerjni.so` (Ghidra/rizin) либо разбор дампа живого потока |
| Содержимое QR-кода привязки, смысл `text_template` | декодировать реальный QR; посмотреть ответ `servers?op=CREATE` |
| Протокол «камера ↔ облако» | только анализ прошивки/трафика камеры — вне APK |
| Открывает ли Cute 2 локальные порты (RTSP/ONVIF/HTTP) | скан камеры при отключённом VPN (AmneziaVPN заворачивает `192.168.0.0/24`) |
| Формат URL WebSocket-превью и голосового канала | живые вызовы `live_preview?op=STREAM`, `voice_message?op=START` |
| Как ограниченный 2FA-токен становится полным | трассировка `lw5`/`ic0` или живой сценарий |
| JSON-форма `recording_schedule`, формат `month` в календаре, единицы зоны детектора движения | чтение кастомных сериализаторов / живые ответы с `"method": "GET"` |
| Лимиты частоты запросов, условия использования | документы Ivideon; наблюдение кодов `TOO_FREQUENT`, `LIMIT_EXCEEDED` |
| Защита приложения (root-детект, проверка целостности) | пиннинга **нет** — установлено; остальное не смотрели |

## 13.4. План живой проверки

Принцип: **сначала только чтение**, по одному запросу, с паузами; ничего не менять на камере и в аккаунте, пока не подтверждён базовый протокол.

| шаг | действие | риск | критерий успеха |
|---|---|---|---|
| 0 | убедиться, что камера привязана и показывает картинку в официальном приложении; выяснить, включена ли 2FA | — |
| 1 | `POST /auth/oauth/token` — **одна** попытка | блокировка при частых неудачах (`TOO_MANY_LOG_IN_ATTEMPTS`) → не повторять в цикле | токен, либо распознанный `proceed_with_2fa` |
| 2 | `POST /servers?op=FIND` с проекцией из [06](06-api-reference.md) | нет | виден сервер Cute 2 и камера `<serverId>:0` |
| 3 | `GET live_preview` (подписанный) | нет | JPEG-файл открывается |
| 4 | `GET live_stream` → `ffprobe`/ffplay, 10–20 секунд | трафик | определён контейнер и кодеки |
| 5 | `POST /events?op=FIND` за последний час; `events?op=GET_TYPES` | нет | список событий |
| 6 | `plugins?op=INVOKE` с `"method": "GET"` для возможностей из `features` | нет (чтение) | текущие настройки детекторов/LED |
| 7 | refresh токена | нет | новый `access_token` |
| 8 | запись — **только осознанно**: `led_switch` on/off как самый безобидный тест | обратимо | светодиод переключился |

<!-- figure: verification-ladder | Лестница живой проверки: от чтения к записи -->

**Не выполнять при проверках:** `servers DELETE`, `cameras DELETE`, `sd_card FORMAT`, `software_version UPDATE`, `auth_credentials UPDATE`, `wifi CONNECT`, `users DELETE`, `access_tokens REVOKE` для токена официального приложения.

Безопасность данных: пароль вводить только в свой клиент локально; токены и подписанные URL не вставлять в переписку, заметки и отчёты — в `--raw`-выводе маскировать `access_token`, `refresh_token`, `hmac_secret`, `cs`, `challenge_token`.

## 13.5. Уточнения по ходу анализа

Выводы первого прохода по коду, которые углублённый анализ опроверг или уточнил.

| первоначальный вывод | как на самом деле |
|---|---|
| `live_preview` авторизуется заголовком Bearer (`@zc0`) | `@l85`: `access_token` в query + подпись; Bearer — только миниатюры и загрузка по готовому URL |
| видео-URL «открывает FFmpeg» | открывает собственный C++-плеер (Boost.Beast + FLV-демуксер); FFmpeg собран без демуксеров и протоколов |
| контейнер потока неизвестен | FLV поверх HTTP(S) |
| использование `api_host` — гипотеза | `api_host` — базовый URL всего авторизованного API и видео |
| хост `streaming.ivideon.com` — для потоков | не используется в 3.7.1 |
| признак 2FA — `limited_to_2fa` | обычная 2FA — ответ 200 `proceed_with_2fa` + `challenge_token`; `limited_to_2fa` — сценарий принудительной настройки 2FA |
| `/idam?op=SHARE` — SSO | выдача доступа к камере по номеру телефона |
| превью-поток — «поток кадров» | WebSocket + protobuf с JPEG |
