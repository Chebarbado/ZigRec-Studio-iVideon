Соглашения APIAPI conventions

Раздел на русском — исходный язык документации.This reference is in Russian. In brief: The ?op= style, ways the token is passed, headers, the envelope, list shapes, projections, seconds vs milliseconds, timeouts, redirects.

Теги: #API5 #JSON #проекции #конверт_ответа #unix_time #таймауты

Правила, общие для всех вызовов «API5» — так в коде называется текущее поколение облачного API Ivideon. Достоверность — [код], если не помечено иначе.

4.1. Стиль

  • Почти всё — POST <ресурс>?op=<ОПЕРАЦИЯ> с JSON-телом (Content-Type: application/json), даже чтение: POST /servers?op=FIND, POST /cameras/{id}?op=GET.
  • Операции: FIND, FIND_ONE, GET, CREATE, UPDATE, UPSERT, DELETE, SET, CONFIGURE, INVOKE, SHARE, REVOKE, POLL, STREAM, START, TEST, CHECK, FORMAT, SCAN, CONNECT, RECOGNIZE, EXPORT, MARK, SELECT, RESEND, SUBMIT, GET_ID, GET_TYPES, RESET_PASSWORD…
  • Настоящий GET — только для бинарных данных: видеопотоки и изображения.
  • Исключение — POST /auth/oauth/token: application/x-www-form-urlencoded, ответ без конверта (03-auth.md).
  • Базовый URL авторизованных вызовов — https://{api_host} из токена (02-architecture.md).

4.2. Авторизация запроса

Интерцептор p000/g58.java:396-467; режим задаётся аннотацией метода сервиса.

режим аннотация как передаётся токен где применяется
обычный нет query-параметр access_token=<token> все вызовы ?op=
Bearer @zc0 заголовок Authorization: Bearer <token> GET /events/{id}/thumbnails, загрузка картинок/клипов по готовому URL
публичный @mn6 никак OAuth-токен, 2FA-вход, регистрация, сброс пароля, device_models?op=RECOGNIZE, access_tokens/{id}?op=REVOKE, customer_clouds?op=FIND
подписанный @l85 access_token в query + cseq + cs live_stream, archive_stream, live_preview — 05-url-signing.md

Пример обычного вызова:

POST https://eu01-api.ivideon.com/servers?op=FIND&access_token=<token>
Content-Type: application/json

{"projection": {"id": 1, "name": 1, "online": 1, "cameras": {"id": 1, "name": 1, "online": 1}}}

Токен в query-строке попадает в логи прокси и серверов — это свойство API. В своих логах маскируйте access_token=… и cs=….

4.3. Заголовки

Приложение не добавляет собственных заголовков по умолчанию: нет ни X-*, ни версии приложения, ни Accept-Language. User-Agent — стандартный для OkHttp: okhttp/5.3.2 (p000/ns7.java:360). Версия и платформа клиента передаются только полями client_version / client_type при входе; язык — полями тел (lang, language).

Нативный плеер, открывая видео-URL, по-видимому, представляется как Boost.Beast/359 [вывод]; WebSocket-превью — фиксированным User-Agent Chrome 27.

Следствие: серверу не по чему отличить сторонний клиент, кроме User-Agent. Обязателен ли определённый User-Agent — не проверено.

4.4. Конверт ответа

Успех (p000/C2619w2.java:64-114):

{"success": true, "result": <значение>}
  • success — строго boolean; result обязателен даже для операций без данных (тогда это {}, "" или null — p000/un6.java);
  • порядок ключей не важен; все прочие ключи верхнего уровня клиент пропускает;
  • идентификатора запроса, total, next, retry_after на уровне конверта клиент не читает.

Ошибка — не-2xx + {"success": false, "code", "message", "details"?} — 10-errors.md.

Списки в result

Приложение принимает три формы списка (p000/C2619w2.java:131-165) — своему клиенту стоит принимать все:

форма пример обработка
массив [{…}, {…}] как есть
объект с items {"items": [{…}, {…}]} берётся items
словарь по id {"100-abc": {…}, "100-def": {…}} в каждое значение вставляется "id": "<ключ>", значения становятся списком

Какую форму отдаёт сервер для конкретного вызова, покажет живая проверка; у /servers?op=FIND это один из главных открытых вопросов.

Пагинация

В запросах — skip и limit. Метаданных пагинации в ответах клиент не читает; конец выборки определяется, видимо, по размеру страницы меньше limit [вывод].

4.5. Проекции

Читающие вызовы (servers FIND/GET, cameras GET, events GET, users GET, folders FIND, notification_settings FIND, exported_records FIND, permission_grants FIND) принимают projection — описание нужных полей в стиле MongoDB:

{"projection": {"id": 1, "name": 1, "cameras": {"id": 1, "online": 1}}}
  • 1 — включить поле; вложенный объект — проекция вложенного документа;
  • встречается форма исключения: {"option": 0, "_others": 1} — «всё, кроме option»;
  • ключи услуг содержат >: "notify>motion".

Методы с проекцией помечены @kr7 — приложение получает result сырой JSON-строкой и разбирает в другом слое; поэтому их ответы типизированы в коде хуже остальных. Что вернёт сервер без projection (всё или минимум) — не проверено; безопаснее передавать проекцию всегда. Готовый образец — в 06-api-reference.md, раздел 6.1.

4.6. Типы данных

тип на проводе детали
дата (поля Date) JSON-число, Unix-секунды, возможна дробная часть до мс: 1700000000 или 1700000000.5 запись — p000/C2647wu.java; чтение — p000/nq2.java: значение ≥ 3.1536·10¹⁰ трактуется как миллисекунды, иначе как секунды
время в миллисекундах (поля long) целое, Unix-мс только: archive_timeline (start_time, end_time, duration) и query-параметры archive_stream
календарная дата строка yyyy-MM-dd archive_calendar
turned_off_until число 0 — включена, -1 — выключена бессрочно, иначе Unix-секунды (p000/ud7.java)
качество q 0 / 1 / 2 low / medium / high
id пользователя в токене — число (owner_id), в телах и путях — строка
id камеры <serverId>:<индекс> двоеточие в пути URL не кодируется
часовой пояс IANA (Europe/Moscow)
null поле опускается serializeNulls не включён
enum строка в нижнем регистре ("wifi", "in_progress") либо число (q, чувствительность звука) значения — в справочнике

Секунды или миллисекунды — главный источник ошибок: events?op=FIND и archive?op=EXPORT принимают секунды, archive_timeline и archive_stream — миллисекунды.

4.7. Сеть, таймауты, повторы

Конфигурация OkHttp (p000/i85.java:76-92):

параметр значение
TLS 1.3 / 1.2 / 1.1 / 1.0; системное хранилище сертификатов. Пиннинга нет (CertificatePinner по умолчанию, в network_security_config.xml нет <pin-set>); cleartext запрещён для ivideon.com и extcam.com
таймауты connect 30 с, read 30 с, write 10 с; общий сторож на вызов — 33 с
редиректы включены (по умолчанию OkHttp)
повторы до 3 попыток на вызов; не повторяются 4xx, ошибки JSON, 2FA
прокси системный

Отсутствие пиннинга означает, что трафик официального приложения можно исследовать MITM-прокси с пользовательским сертификатом (на Android ≥ 7 — с поправкой на доверие только системным CA). Это резервный способ живой проверки, если статического анализа не хватит.

О редиректах. api.ivideon.com отвечает редиректом на региональный хост (eu01-api.ivideon.com) — [проверено] для запроса к корню. OkHttp при 301/302 превращает POST в GET и теряет тело; при 307/308 — сохраняет. Каким кодом сервер редиректит именно POST /auth/oauth/token, неизвестно. Своему клиенту: не следовать редиректам автоматически для POST — получив 3xx, повторить тот же POST с тем же телом на Location.

4.8. Частота запросов

Интервалы, которые использует само приложение — разумный верхний предел и для своего клиента:

что интервал
опрос токена привязки 3 с
опрос состояния сервера 5 с
опрос пакетного запроса 1 с
поток превью в сетке камер 1 кадр/с

Лимиты сервера неизвестны. Коды TOO_MANY_LOGIN_ATTEMPTS, TOO_FREQUENT, LIMIT_EXCEEDED показывают, что ограничения есть.
