# Ivideon: документация для разработчиков

Результаты реверс-инжиниринга Android-приложения **Ivideon** (`com.ivideon.client` 3.7.1) и всё необходимое, чтобы написать собственный клиент/драйвер облачной камеры Ivideon — в первую очередь **Ivideon Cute 2**.

> **Статус достоверности.** Протокол восстановлен **статическим анализом** декомпилированного кода. Авторизованных запросов к живому API ещё не было. В тексте используются пометки **[код]**, **[вывод]**, **[гипотеза]**, **[проверено]** — см. [01-methodology.md](01-methodology.md), раздел 1.6. План живой проверки — в [13-open-questions.md](13-open-questions.md).

## Протокол за одну минуту

1. **Вход**: `POST https://api.ivideon.com/auth/oauth/token` — OAuth2 password grant, клиент `android-client` с пустым секретом (Basic), форма с полями устройства. В ответе — `access_token`, `refresh_token`, **`api_host`**, **`hmac_secret`**. При включённой 2FA вместо токена приходит `proceed_with_2fa` + `challenge_token`.
2. **API**: всё дальнейшее — на `https://{api_host}`. Стиль — `POST /ресурс?op=ОПЕРАЦИЯ&access_token=…` с JSON-телом; ответ — `{"success": true, "result": …}`; ошибка — не-2xx + `{"success": false, "code", "message"}`.
3. **Камеры**: `POST /servers?op=FIND` с проекцией. Сервер = устройство, камера = канал; id камеры — `<serverId>:<индекс>`. Поле `features` сообщает, что умеет камера.
4. **Картинка**: `GET /cameras/{id}/live_preview?q=0..2` → JPEG.
5. **Видео**: `GET /cameras/{id}/live_stream?q=…&video_codecs=h265,h264&audio_codecs=…` → **FLV поверх HTTPS**. Архив — `archive_stream` со `start_time` в миллисекундах; перемотка = новый URL.
6. **Подпись**: URL из п. 4–5 подписываются: `cseq=<сессия>:<счётчик>`, `cs = hex(HMAC_SHA1(hmac_secret, hex(SHA1("GET:<path>:<query>:"))))`.
7. **Камера и телефон напрямую не общаются** — только через облако. Привязка: сервер генерирует QR-код с параметрами Wi-Fi, камера читает его объективом.

## PDF-версия

Вся документация одним файлом — `docs/ivideon-developer-docs.pdf` (свёрстана в LaTeX). Первоисточник — Markdown-файлы этого каталога; PDF пересобирается из них одной командой из корня проекта:

```bat
python docs\latex\build.py
```

Подойдёт любой Python 3 — сторонних модулей скрипт не использует. Он склеивает главы, прогоняет их через pandoc с фильтром `docs/latex/filters.lua` и компилирует `docs/latex/main.tex` движком Tectonic. Каталог `docs/latex/build/` — промежуточные файлы, его можно удалять.

**PDF кликабелен.** Кроме оглавления, списка иллюстраций и закладок, ссылками становятся:

| что в тексте | куда ведёт |
|---|---|
| «глава 3», «раздел 3.4», «§13.4» | на главу или раздел |
| путь к исходнику — `p000/g58.java:396-467`, а также короткое имя класса — `g58`, `C2199ku` | на файл в `decompiled-ivideon-3.7.1/sources/` |
| любой существующий файл проекта — `zig-client/src/sign.zig` | на этот файл |
| URL без подстановок — `https://api.ivideon.com` | на этот адрес |
| хэштег под заголовком главы и на титуле | в «Указатель хэштегов» в конце, а оттуда — в главы с этим тегом |
| «↑ Оглавление» внизу каждой страницы | к оглавлению |

Кликабельный код набран синим, обычный — коричневым. Ссылки на файлы — относительные: они работают, пока PDF лежит в `docs/` внутри проекта; при открытии файла просмотрщик может спросить подтверждение.

**Хэштеги.** Строка `**Теги:** #тег1 #тег2` под заголовком главы (и в этом файле — общий набор для титула) при сборке превращается в кликабельные хэштеги; указатель в конце PDF и ключевые слова в свойствах файла собираются из этих строк автоматически.

**Инфографика.** Рисунки — TikZ-файлы в `docs/latex/diagrams/`. Место рисунка в тексте задаёт HTML-комментарий, невидимый при обычном просмотре Markdown: `<!-- figure: имя | подпись -->`. Диаграммы mermaid при сборке заменяются своими TikZ-двойниками — при изменении диаграммы в Markdown двойника нужно поправить вручную.

## Рамки

Исследование ведётся для совместимости с собственной камерой и собственным аккаунтом. В документации нет учётных данных и токенов; все идентификаторы в примерах вымышлены. `android-client` — публичная константа приложения. Перед живыми проверками прочтите §13.4: единичные запросы, сначала только чтение.
